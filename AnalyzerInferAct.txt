from datetime import datetime, time, timedelta
import pytz

# Configure timezones and batch constraints
EST_TZ = pytz.timezone("America/New_York")
BATCH_START_TIME = time(20, 0, 0) # 8:00 PM EST

def get_current_business_run_date(reference_time: datetime = None) -> datetime:
    """
    Calculates the boundary anchor for the current Logical Batch Window.
    
    Rules:
    - If reference_time is >= 8:00 PM EST, the batch window belongs to TODAY.
    - If reference_time is < 8:00 PM EST, the batch window belongs to YESTERDAY.
    
    Returns:
        A timezone-aware datetime object set to 8:00 PM EST of the active cycle.
    """
    if reference_time is None:
        reference_time = datetime.now(EST_TZ)
    else:
        # Ensure reference time is localized to EST
        if reference_time.tzinfo is None:
            reference_time = EST_TZ.localize(reference_time)
        else:
            reference_time = reference_time.astimezone(EST_TZ)
            
    # Create the baseline cutoff for the reference date
    target_cutoff = reference_time.replace(
        hour=BATCH_START_TIME.hour, 
        minute=BATCH_START_TIME.minute, 
        second=0, 
        microsecond=0
    )
    
    if reference_time >= target_cutoff:
        return target_cutoff
    else:
        return target_cutoff - timedelta(days=1)

def validate_autosys_run(last_start_time_raw: str) -> dict:
    """
    Validates if an AutoSys job's execution timestamp belongs to the current batch window.
    
    Args:
        last_start_time_raw: ISO timestamp string from AutoSys event logs.
        
    Returns:
        dict: Evaluation status containing flags and the logical business run date string.
    """
    # 1. Parse and normalize the incoming AutoSys timestamp
    try:
        job_start_dt = datetime.fromisoformat(last_start_time_raw)
        if job_start_dt.tzinfo is None:
            job_start_dt = EST_TZ.localize(job_start_dt)
        else:
            job_start_dt = job_start_dt.astimezone(EST_TZ)
    except ValueError:
        return {"error": "Invalid date format. Use ISO-8601 format."}

    # 2. Get the current active business run window anchor
    now_est = datetime.now(EST_TZ)
    current_batch_anchor = get_current_business_run_date(now_est)
    
    # 3. Perform look-back comparison math
    # The run is valid for today's batch only if it started after the batch window flipped open
    is_current_run = job_start_dt >= current_batch_anchor
    
    return {
        "is_valid_for_current_batch": is_current_run,
        "business_run_date": current_batch_anchor.date().isoformat(),
        "job_start_est": job_start_dt.isoformat(),
        "batch_window_opened_est": current_batch_anchor.isoformat()
    }

## 2. Structural Fix: Breaking "Rule Bloat" & Regressions

### The Problem: The "if/else" Rigmarole
Writing continuous patches as global `if/elif/else` logical structures leads to tight control-flow coupling. Modifying logic to fix one edge case inherently causes regressions across your regular batch runs, leading to a daily ritual of playing whack-a-mole.

### The Permanent Solution: Scenario-Based Coding Matrix
1. **Isolate Scenarios:** Break down every production anomaly into its own self-contained file or class implementing a strict `matches()` and `generate_remediation_recipe()` interface contract.
2. **No Shared State:** If a bug is introduced into a newly added scenario rule, it is physically locked inside that class. It cannot contaminate stable execution paths.
3. **Crash Insulation:** Wrap the matrix evaluator loop in error-catching blocks to prevent individual rule failures from bringing down the entire monitoring agent fabric.

## 3. The 11 Core AutoSys Production Scenarios Reference

## 4. Bypassing TOCTOU Race Conditions via Oracle DB MCP

### The Trap: `autorep -j` Overheads
Invoking `autorep -j` via a Unix shell MCP triggers severe Operating System overhead. The OS must fork a new process, load environment binaries, and set up a heavy CLI stdout string table. This creates an execution lag of **200ms to 1500ms**, opening a wide Time-of-Check to Time-of-Use (TOCTOU) race condition window where statuses change while the agent is processing text string regex patterns.

### The Solution: Direct Oracle Database Verification
The AutoSys underlying Oracle database engine (the Event Server) is the actual scheduler engine. Status commits occur instantly in the database table `ujo_jobstatus` *before* downstream jobs are evaluated. 

By setting up an optimized, persistent read-only connection pool directly to the Oracle instance, the **Fixer Agent** performs an explicit, sub-5ms atomic "Just-In-Time" query right before triggering its remediation command. If the live status has changed, the action aborts immediately, locking out race conditions.

#### AutoSys Database Reference Map (`ujo_jobstatus.status`)
* `1` = **RUNNING**
* `3` = **STARTING**
* `4` = **SUCCESS**
* `5` = **FAILURE**
* `6` = **TERMINATED**
* `7` = **ON_HOLD**
* `8` = **QUE_WAIT**
